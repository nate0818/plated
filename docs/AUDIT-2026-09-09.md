# Plated product readiness audit

**Date:** 9 September 2026
**Scope:** `main` at `64f764c` (`They're in promotes Invited to joined in place…`)
**Auditor:** Cursor cloud agent, Linux environment (no Xcode, no iOS Simulator, no device)
**Product:** Native iOS household dinner planner — SwiftUI + SwiftData, CloudKit shares for household and Table, widgets, web join pages, a small Supabase directory

This is a code-and-docs audit. It does not implement product changes. Ratings below are evidence-based: a feature that compiles and has tests is not the same as a feature proven on two Apple IDs.

---

## Executive summary

Plated is much further along than `README.md` claims. The README still says **“v0.1 — scaffold”** with a roadmap whose “Next” items (widgets, Siri, drag-and-drop, URL import, CloudKit household share) are already in the tree and have been through TestFlight builds 11–20. `MARKETING_VERSION` is `0.1.0`; `CURRENT_PROJECT_VERSION` is **24**. Treat README as historical. The live register is `DESIGN.md`, `docs/household.md`, `docs/plan-share.md`, `docs/notifications.md`, and `docs/open-decisions.md`.

**What is actually built:** a four-tab iOS app (Plan, Recipes, Groceries, Table) with Sign in with Apple, a CloudKit household that crosses Apple IDs, a separate Table share for dishes and plates, grocery rollup that includes other phones’ nights, cook mode, awards, recipe import, widgets, App Intents, and `plated.food` join pages. Sync law is unusually well documented and the unit suite is strong on the digest/merge/copy paths that have already burned this repo.

**What is not ship-ready as a household product:** the pipes that only exist between two real iCloud accounts. Silent CloudKit push is explicitly **unverified**. Removing one link-joined participant from a `.readWrite` public share is written against a behaviour Apple has not promised. Invite APNs is documented as half-deployed. Discover exists as a screen and a stamp, but incoming posts are forced `isDiscover: false` and the screen has no production entry point. The share extension source is retained and **not in the Xcode project**. There is no CI.

**Verdict for this week:** keep TestFlight as the distribution channel; do not treat App Store as next. The core solo loop (plan → cookbook → grocery → cook) is the most ready surface. The household/Table loop is the product, and it is **Fragile** until a three-phone rehearsal of join, plan, grocery, remove, and background notification has been run once and written down.

## 1. Architecture

### 1.1 Native modules

| Target | Path | Role | Readiness |
|---|---|---|---|
| **Plated** | `Plated/` | App: onboarding → `RootView` → `MainShellView` (four tabs). No `ContentView.swift`. | Built |
| **PlatedWidgets** | `PlatedWidgets/` | WidgetKit + Live Activity. App group reader. `TonightWidget` is first in `PlatedWidgetsBundle` (icon-menu rule). | Built; tokens gated |
| **PlatedShareExtension** | `PlatedShareExtension/` | Share sheet → app-group inbox → `plated://import-shared` | **Not in the Xcode project** |
| **PlatedTests** | `PlatedTests/` | 288 unit tests, 14 files | Mac/simulator only |

Entry: `PlatedApp` constructs `PlatedStore.shared`, installs `ShareAcceptor` as `UIApplicationDelegate`, then `RootView`. `HouseholdSync.ensureObserving()` runs in `PlatedApp.init` and every App Intent `perform` — not inside the store’s static initialiser (main-actor / watcher-timing law).

Compile flag `PLATED_CLOUDKIT` is on Debug and Release. `#if PLATED_CLOUDKIT` wraps every `CKContainer` touch; an unentitled build would otherwise raise an ObjC exception `try?` cannot catch.

### 1.2 Data ownership (the load-bearing split)

Three tiers. Mixing them is how this repo has already produced ping-pong counts and a hung test host.

**SwiftData + CloudKit `.automatic` mirror** (`PlatedStore.schema`): `Recipe`, `Ingredient`, `RecipePhoto`, `PlannedMeal` (this phone’s nights only), `HouseholdMember`, `Gathering`, `GroceryItem`, `TablePost` / `TableComment` (host + absorbed remotes), `DirectMessage`, `PlatedNotification`, `HouseholdProfile`. Same Apple ID, two devices.

**Hand-written shared zones:**

| Zone | Root | Who sees |
|---|---|---|
| `PlatedTable` | `table-root` | Dishes, asks, plates, comments. Guests allowed. |
| `PlatedHousehold` | `household-root` | Roster, recipes, grocery marks, `PlatedHouseholdPlan` nights. Members only. |

Table records use the reserved `PlatedDish*` prefix so the SwiftData mirror does not adopt them as ghosts (`TableShare.assertNoEntityCollision()`, `TablePost` is the documented exception).

**App-group JSON, per device, not mirrored:** `TableLedger` (plates/ballots), `PlanLedger` (other phones’ nights), `CookLedger`, `GroceryMarks`, `TableOutbox`, `HouseholdOutbox`, `plan-share.json`, `plan-edits.json`.

**Law:** a night someone else planned is a `PlanLedger.Entry`, never a `PlannedMeal`. Folding title/cook/servings into `PlannedMeal` is two writers. The allowed exception is a `removed` flag: the author’s phone deletes that one `PlannedMeal` and there is nothing left to disagree about (`RemovedNights`, `docs/plan-share.md`).

### 1.3 Sync flow

```
foreground / push / share-accept / scene
        │
        ▼
  TablePull.pull (serial)
        ├─ HouseholdShare.refreshMembership
        ├─ TableOutbox.drain → TableClaimOutbox → HouseholdOutbox.drain
        ├─ TableShare.fetchChanges → ShareAcceptor.absorb
        └─ HouseholdShare.fetchChanges → household merge + PlanLedger.absorb
```

Conflicts: household rows use server fetch + `modifiedAt` (version, not wall clock); deletions win. Plates/ballots are per-author sets (commutative). Grocery marks last-writer-wins on a key. Placeholder CloudKit identity (`local-{UUID}`) blocks plan publish until `TableIdentity.confirmAndReattribute`.

Offline: local store remains; outboxes replay; `TableSync.AccountState.temporarilyUnavailable` is “later”, not “broken”.

### 1.7 Web

Native relationship: iCloud share URLs are wrapped as `https://plated.food/join/…` (`Invitation.swift`). Installed app opens via AASA; web is the no-app fallback. Join buttons send people to TestFlight, not a 404 App Store listing.

### 1.8 Coupling risks

1. **Name vs `authorID`** — still mixed; rename rewrites many fields but not comment `@mentions`.
2. **Widget token fork** — mitigated by `scripts/check-tokens` on `make phone` and TestFlight.
3. **Single `onOpenURL`** in `RootView`; shell uses `LinkRelay`. A second handler would double-route.
4. **`TablePull` serial bottleneck** — household drain blocks Table fetch.
5. **Stale comments as spec** — `TableSync` header is the current exhibit.
6. **`PlatedStore` singleton** — a second `ModelContainer` in-process is unsupported.

## 4. Reliability

### 4.1 Crash and store safety

`PlatedStore` `fatalError`s if the container cannot be created. Intentional: an unreadable live store must abort, and a fallback container would poison `CloudSync`’s watcher. `migrateLegacyStoreIfNeeded()` is the precious path — CLAUDE.md forbids simplifying it to an existence check. There is **no automated migration test**.

Force-unwraps in production are few and mostly static URLs / preview `try!`. `DishView` force-unwraps a `CIFilter` name.

### 4.2 Network and sync failure

- Directory calls fail **silent by design** (`Directory.register` comment).
- Outbox drops a row after 20 failures (print only). A Production CloudKit schema miss is this failure: TestFlight therefore runs `scripts/check-schema`. **This environment: 153 fields, matches deployed manifest.** That is code-vs-manifest, not a live console confirmation.
- Empty CloudKit lists must omit the key (`[]` mints the wrong type forever).
- CloudKit has no Bool; `TableShare.int` is the bridge.
- Two `.sheet` modifiers on one view are undefined; invite and contact picker go through UIKit `InviteFlow`.

### 4.3 Auth and invite races

Recent `main` work is exactly here: Invited rows stuck when the joiner accepted before the host’s row landed; “They're in” promotion; ghost seats. Unit tests exist (`SeatsTests`, `HouseholdSyncTests`, `TableAcceptTests`). Remaining: §17 Remove, §20 history, public-link forwarding.

### 4.4 Concurrency

`TablePull` is serial (good). `PlanLedger.photo(for:)` historically wrote `nil` on every miss and spun the main actor at 99% — guarded now (`if photos[name] != nil`). `@Observable` services must not write on a read. App Intents use the same store and must call `HouseholdSync.ensureObserving()`.

### 4.5 Push

Three pipes (`docs/notifications.md`): local schedule, CloudKit silent → local banner, directory APNs for invites. Silent push: unverified on sim, force-quit and Low Power Mode drop it, bell catches up on next open (60s throttle). Invite APNs: not sending yet.
